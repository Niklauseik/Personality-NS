# SPACE: core training code

Core DPO training implementation accompanying **More Than Just Style: Benchmarking Personality Influence in Large Language Models**.

This release contains training code only. It does not distribute datasets, base checkpoints, trained adapters or merged model weights, evaluation inputs, raw responses, experimental results, or manuscript sources. It is not a complete reproduction package for all SPACE benchmark results.

## Included implementation

- `training/train.py`: single-GPU LoRA DPO with a separate frozen base reference, loss-based early stopping, resumable checkpoints, and merged export.
- `training/train_llama8b.py`: the Llama 3.1 8B runner, using the same base model with adapters disabled as its reference.
- `stage1/dpo_training_chat.py`: preference-pair construction and chat-template formatting.
- `common/pipeline_utils.py`: the dimension definitions and opposite-pole helper required by training.
- `training/make_model_manifest.py`: checkpoint-integrity manifest generation.

The two training runners and preference builder are retained from the paper's minimal anonymous code supplement. The obsolete fixed-six-epoch training package is not used. The shared helper module is reduced to the functions required by these runners, without changing their bodies.

## Environment and external inputs

Use Python 3.10 or newer and a compatible CUDA GPU environment. Install `requirements.txt`. The original locked package versions are not included; the runners record the actual package versions in `recipe.json`. A full GPU training run has not been repeated as part of packaging this release.

Obtain base checkpoints separately under their providers' terms. The runners cover the model families used in the paper: Llama 3.2 3B, Llama 3.1 8B, Qwen2.5 3B and Qwen2.5 7B Instruct. Use the dedicated 8B runner for Llama 3.1 8B.

Supply preference data separately. The paper uses the English behavior split of Machine Mindset. The loader expects paired JSON lists at `datasets/training_raw/en_<dimension>_<subtype>.json`, with `instruction`, `input`, and `output` fields. Opposite-pole files must have aligned row order and matching instructions/context. No example records or dataset files are bundled.

| Dimension | Preferred subtype values |
| --- | --- |
| `energy` | `extraversion`, `introversion` |
| `information` | `sensing`, `intuition` |
| `decision` | `thinking`, `feeling` |
| `execution` | `judging`, `perceiving` |

## Training

Run commands from this package directory. Replace checkpoint and output paths with your own locations.

```bash
python -m pip install -r requirements.txt
python -m training.make_model_manifest --model-path checkpoints/base
python -m training.train --dimension decision --preferred thinking --base-model-path checkpoints/base --output outputs/thinking
python -m training.train --dimension decision --preferred feeling --base-model-path checkpoints/base --output outputs/feeling
```

For Llama 3.1 8B, replace `training.train` with `training.train_llama8b`.

The reference recipe uses learning rate `1e-5`, DPO beta `1.0`, seed `42`, per-device batch size `16`, gradient accumulation `2`, LoRA rank `32`, alpha `64`, and dropout `0.1`. The learning rate is constant. Early-stop monitoring uses training-loss windows of 100 steps after one epoch, stopping after two windows without a 5% relative improvement. The 20-epoch limit is an emergency ceiling, not the successful stopping criterion. Reaching it without a loss plateau is marked incomplete.

Runtime outputs may contain local paths and model/checkpoint hashes. They are generated by a user's own run and are excluded from this source release.
